# 32-bit Pipelined ALU Verification Using SystemVerilog and UVM

## 1. Project Overview

This project focuses on the functional verification of a 32-bit pipelined Arithmetic Logic Unit (ALU) using SystemVerilog and the Universal Verification Methodology (UVM).

An ALU is a fundamental digital component that performs arithmetic and logical operations. Pipelining divides processing into multiple stages to support efficient operation across clock cycles.

## 2. Project Objectives

- Verify arithmetic and logical operations.
- Validate correct pipeline behavior across multiple stages.
- Verify input and output valid/ready handshaking.
- Check status flags generated by ALU operations.
- Detect incorrect results, data corruption, and pipeline timing issues.
- Develop a reusable UVM-based verification environment.

## 3. Design Overview

The ALU accepts operands and an operation code, processes the requested operation through a three-stage pipeline, and produces the corresponding result.

The design supports multiple operation codes and status flags, according to the RTL implementation.

Key features include:
- 32-bit input operands and result data.
- Three-stage pipelined processing.
- Arithmetic and logical operations.
- Valid/ready handshaking.
- Status flags such as zero, carry, overflow, negative, parity, and saturation, where implemented.
- Operand forwarding support, where implemented.

## 4. Verification Environment

The verification environment is developed using SystemVerilog and UVM.

The main components include:

- **Sequence:** Generates ALU transactions and test scenarios.
- **Sequencer:** Supplies transactions to the driver.
- **Driver:** Drives operands, operation codes, and handshake signals.
- **Monitor:** Observes input transactions and output results.
- **Scoreboard:** Compares DUT outputs against expected results from a reference model.
- **Reference Model:** Calculates expected results for supported ALU operations.
- **Functional Coverage:** Tracks operation types, operand conditions, and relevant corner cases.
- **Assertions:** Checks selected protocol, handshake, and pipeline properties.

## 5. Verification Scenarios

The verification plan includes the following scenarios, where implemented:

- Basic arithmetic operations.
- Logical operations.
- Boundary and corner-case operands.
- Zero-result conditions.
- Carry and overflow conditions.
- Negative-result conditions.
- Valid/ready handshake behavior.
- Pipeline latency and transaction ordering.
- Multiple transactions across consecutive clock cycles.
- Operand forwarding behavior.
- Reset and recovery behavior.
